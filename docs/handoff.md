# 引継ぎ資料 — 家計簿PWA

このドキュメントは、要件定義フェーズ（claude.ai での対話）から製造フェーズ（Claude Code）へ引き継ぐためのものです。
要件そのものは `docs/requirements.md` を正とし、ここには背景・判断理由・進め方を書きます。

## 1. プロジェクトの背景

- 作る人はスマホアプリ開発が初めて。iPhone は持っているが Mac は持っていない
- 「自分の家計簿を管理したい」が出発点。将来は家族も使うが、家計は各自で独立させる
- iOS 向けだけを考慮する。Android は動けばよい程度

## 2. なぜこの構成にしたか

| 検討したこと | 結論 | 理由 |
|---|---|---|
| ネイティブアプリ（Swift / Flutter / React Native） | 採用しない | Mac がないと実機ビルドができない。クラウドビルド（Expo EAS など）を使う手もあるが、Apple Developer Program の年会費が必須になる |
| PWA | 採用 | Windows だけで開発でき、費用ゼロ。ストア審査も開発者登録も不要。家計簿に必要な機能は PWA で十分 |
| データを端末内に置く | 採用 | サーバー・ログインが不要。家族も各自独立した家計簿なので、共有基盤は要らない |
| クラウド保存 | 第2段階で任意 | 機種変更やバックアップを楽にしたくなったときに検討。それまでは JSON エクスポートで代用 |

## 3. 技術スタック（提案）

Claude Code が最初に環境構築するときの前提です。理由があれば変更してよいが、変更時は本ファイルも更新すること。

| 役割 | 選定 | 理由 |
|---|---|---|
| ビルド | Vite | 設定が少なく、PWA プラグインが整っている |
| UI | React + TypeScript | 情報量が多く、Claude Code が扱いやすい。型があると初心者でもエラーに気づきやすい |
| ローカル DB | Dexie.js | IndexedDB を素で触るより大幅に簡潔。エクスポート / インポートも書きやすい |
| PWA | vite-plugin-pwa | manifest と Service Worker を自動生成 |
| ルーティング | React Router（または軽量な自前実装） | 画面は 4 つなので、大げさにしない |
| テスト | Vitest | Vite と相性がよい。集計ロジックのみテスト対象 |
| CSS | 素の CSS または CSS Modules | ライブラリを増やさない |
| デプロイ | GitHub Actions → GitHub Pages | push するだけで公開される |

## 4. ディレクトリ構成（案）

```
kakeibo/
├── CLAUDE.md
├── docs/
│   ├── requirements.md
│   └── handoff.md
├── public/
│   └── icons/            # ホーム画面用アイコン
├── src/
│   ├── data/             # Dexie の定義とリポジトリ層（唯一 DB を触る場所）
│   ├── logic/            # 集計・予算引き継ぎなどの純粋関数（テスト対象）
│   ├── pages/            # Home / Entry / Calendar / Settings
│   ├── components/       # 共通部品
│   └── main.tsx
├── .github/workflows/deploy.yml
├── index.html
├── package.json
└── vite.config.ts
```

## 5. 作業ステップ

各ステップの終わりに `npm run dev` で動作確認し、コミットする。ステップ 2 以降は iPhone での確認も適宜行う。

### ステップ 0：環境準備（ユーザー側）
1. Node.js（LTS）、Git、VS Code をインストール
2. GitHub アカウントを用意し、空のリポジトリ `kakeibo` を作成（Public にすると GitHub Pages が無料で使える）
3. Claude Code をインストール（手順は公式ドキュメント https://docs.claude.com/en/docs/claude-code/overview を参照）
4. リポジトリを clone し、この docs/ と CLAUDE.md を配置して最初のコミット

### ステップ 1：プロジェクト雛形
- Vite + React + TypeScript で初期化
- Dexie / vite-plugin-pwa / Vitest を導入
- `vite.config.ts` の `base` を `/kakeibo/` に設定
- GitHub Actions のデプロイ設定を追加し、空のページが GitHub Pages で表示されることを確認
- 完了条件：iPhone Safari で URL を開き「ホーム画面に追加」できる

### ステップ 2：データ層
- Dexie でテーブル定義（entries / categories / budgets）
- リポジトリ層の関数（追加・更新・削除・月別取得）
- 初回起動時の初期カテゴリ投入
- 完了条件：ブラウザの開発者ツールでデータが保存されていること

### ステップ 3：集計ロジック
- 月別の収入合計・支出合計
- カテゴリ別の当月支出と残額
- 予算の引き継ぎ（未設定月は直近の設定値）
- 完了条件：Vitest のテストが通る

### ステップ 4：入力画面
- 新規登録・編集・削除
- 完了条件：iPhone で記録を登録し、再起動後も残っている

### ステップ 5：ホーム画面
- カテゴリ別の予算 / 実績 / 残額、全体合計、警告色、月切り替え
- 完了条件：入力した記録が正しく集計されて表示される

### ステップ 6：カレンダー画面
- 月表示、日別支出、日タップで一覧、一覧から編集へ
- 完了条件：入力画面・ホームと行き来できる

### ステップ 7：設定画面
- カテゴリ管理、月予算設定、JSON エクスポート / インポート
- 完了条件：エクスポートしたファイルを別端末（または削除後）にインポートして復元できる

### ステップ 8：仕上げ
- アイコン、アプリ名、テーマカラー
- オフライン動作の確認（機内モードで全画面が動くこと）
- 未使用コードの整理、README の作成

## 6. iPhone での確認方法

1. GitHub に push すると GitHub Actions が自動でビルドし、数分で `https://<ユーザー名>.github.io/kakeibo/` に反映される
2. iPhone の Safari で URL を開き、共有ボタン →「ホーム画面に追加」
3. ホーム画面のアイコンから起動すると全画面で動く
4. 更新が反映されないときは、ホーム画面のアプリを一度閉じて再度開く。それでも古いままなら Safari の設定からサイトデータを削除して再追加する（Service Worker のキャッシュが残っているため）
5. 開発中の細かい確認は PC のブラウザ（開発者ツールでスマホ幅に切り替え）で行い、iPhone では節目ごとに確認する

注意：Safari のサイトデータを削除すると IndexedDB の家計簿データも消える。開発中はテストデータで運用し、本番運用を始めたら JSON エクスポートを習慣にすること。

## 7. Claude Code に依頼するときのコツ

- 最初のセッションでは「CLAUDE.md と docs/ を読んで、ステップ 1 から始めて」と伝える
- 1 回の依頼は 1 ステップ程度に区切ると、確認と修正がしやすい
- 「なぜそうしたか」を毎回聞いてよい。学習を兼ねている前提を Claude Code は CLAUDE.md で把握している
- 要件にない機能を提案されたら、その場で採否を決めて `docs/requirements.md` に反映してもらう
- 設計や方針を変えたときは `docs/handoff.md` と `CLAUDE.md` の更新も依頼する

## 8. 用語

| 用語 | 意味 |
|---|---|
| PWA | Webサイトをアプリのようにインストールして使う仕組み。ホーム画面に追加、オフライン動作などができる |
| Service Worker | ブラウザの裏で動くスクリプト。ファイルをキャッシュしてオフライン動作を可能にする |
| IndexedDB | ブラウザに内蔵されたデータベース。端末内にデータを保存する |
| GitHub Pages | GitHub のリポジトリを無料で Web サイトとして公開する機能 |
| GitHub Actions | push をきっかけに自動でビルドやデプロイを実行する仕組み |
| manifest | アプリ名・アイコン・起動方法などを定義するファイル。ホーム画面追加時に使われる |
