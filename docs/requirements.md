# 家計簿PWA 要件定義書

- 作成日：2026-09-11
- ステータス：確定（第1段階）

## 1. 目的

個人の収支を記録し、カテゴリごとの月予算に対する残額を把握する。
家族も同じアプリを使えるが、家計簿はあくまで各自のものであり、データは混ぜない。

## 2. 利用環境

- iPhone の Safari から「ホーム画面に追加」して使う PWA（Progressive Web App）
- オフラインで入力・閲覧できる
- ソースは GitHub で管理し、GitHub Pages で公開する
- 認証なし、サーバーなし。家族には同じ URL を共有するだけ
- 開発機は Windows。Mac は使わない

## 3. 画面構成

### 3.1 ホーム
- 当月のカテゴリ別「予算 / 実績 / 残額」を一覧表示
- 上部に当月の全体合計（支出合計、収入合計、予算合計と残額）
- 残額が少ない（予算の 10% 未満）またはマイナスのカテゴリを色で警告
- 「＋」ボタンで入力画面へ
- 前月・翌月へ切り替えられる

### 3.2 入力
- 項目：日付（既定は今日）、種別（収入 / 支出）、金額、カテゴリ、メモ（任意）
- 新規登録、既存記録の編集・削除
- 金額は整数（円）。0 以下は登録不可
- 保存後はホームに戻る

### 3.3 カレンダー
- 月表示。各日のセルに支出合計を表示
- 日をタップするとその日の記録一覧を表示し、各記録から編集画面へ遷移できる
- 前月・翌月へ切り替えられる

### 3.4 設定
- カテゴリ管理：追加、名前変更、並び替え、非表示（削除ではなく非表示にし、過去の記録との整合を保つ）
- 月予算設定：支出カテゴリごとに当月の予算を入力。未設定の月は前月の値を引き継ぐ
- データ管理：JSON エクスポート（ファイル共有）、JSON インポート（既存データを置き換えるか確認したうえで実行）

## 4. データ

すべて端末内（IndexedDB）に保存する。保存処理は 1 つのモジュールに集約し、将来クラウド保存へ差し替えられるようにする。

### 4.1 記録（Entry）
| 項目 | 型 | 備考 |
|---|---|---|
| id | string | UUID |
| date | string | YYYY-MM-DD |
| type | "income" \| "expense" | |
| amount | number | 整数（円） |
| categoryId | string | |
| memo | string | 空文字可 |
| createdAt | string | ISO 8601 |
| updatedAt | string | ISO 8601 |

### 4.2 カテゴリ（Category）
| 項目 | 型 | 備考 |
|---|---|---|
| id | string | UUID |
| name | string | |
| type | "income" \| "expense" | |
| sortOrder | number | |
| isActive | boolean | false は非表示 |

### 4.3 予算（Budget）
| 項目 | 型 | 備考 |
|---|---|---|
| categoryId | string | 支出カテゴリのみ |
| yearMonth | string | YYYY-MM |
| amount | number | 整数（円） |

### 4.4 エクスポート形式
```json
{
  "version": 1,
  "exportedAt": "2026-09-11T10:00:00.000Z",
  "categories": [],
  "budgets": [],
  "entries": []
}
```

## 5. 集計ルール

- 月の区切りは 1 日〜月末
- 予算対象は支出カテゴリのみ。収入は記録と月合計に含めるが予算管理はしない
- 残額 = 予算 − 当月の該当カテゴリ支出合計
- 予算が未設定の月は、直近の設定済み月の値を引き継ぐ。一度も設定されていなければ「未設定」と表示
- ホーム上部の「予算合計」は予算が設定されているカテゴリの予算の合計。「残額」はそれらのカテゴリの残額の合計（予算未設定カテゴリの支出は差し引かない）
- 非表示カテゴリは、当月に支出があるときだけホームの一覧に表示し、支出合計にも含める（過去の記録との整合のため）

## 6. 初期カテゴリ

- 支出：食費、日用品、交通費、住居費、水道光熱費、通信費、医療、娯楽、交際費、その他
- 収入：給与、その他収入

初回起動時に自動生成する。

## 7. 非機能要件

- iPhone Safari（最新の iOS）で動作すること。他ブラウザは動けばよい
- ホーム画面に追加すると全画面（standalone）で起動する
- オフラインで全機能が動作する（Service Worker によるキャッシュ）
- 端末内のデータは、アプリを再起動しても消えない
- 画面は縦向きのスマホ幅を前提に設計する

## 8. 第1段階でやらないこと

- 固定費の自動登録
- 支払方法（現金 / カード）の記録
- 銀行・クレジットカード連携
- レシート OCR
- プッシュ通知
- ログイン、クラウド保存、複数端末同期
- 家族間でデータを見せ合う機能

## 9. 第2段階（家族が使い始めるとき）

- 必須の追加開発はなし。同じ URL をホーム画面に追加してもらえば、各自の端末で独立した家計簿として使える
- 任意で検討：機種変更やバックアップを楽にするためのクラウド保存（各自ログイン、データは本人のみ閲覧）
- 家族間でデータを共有・合算する機能は作らない

## 10. 決定事項の記録

| 論点 | 決定 | 理由 |
|---|---|---|
| ネイティブか PWA か | PWA | Mac がなく、Apple Developer Program の費用も不要にできる |
| 保存先 | 端末内（IndexedDB） | サーバー不要。家族もデータを混ぜないため共有基盤が要らない |
| 予算の単位 | カテゴリごとの月予算 | 使いすぎをカテゴリ単位で把握したい |
| 月の区切り | 1 日〜月末 | シンプルさを優先 |
| 第1段階の表示 | ホーム（残額一覧）とカレンダー | グラフは後回し |
| 家族利用 | 各自独立 | 家計を合算する予定がない |
